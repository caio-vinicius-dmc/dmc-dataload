1. Visão Geral do Pipeline Builder

O Pipeline Builder é o editor visual de pipelines de dados do DMC DataLoad. Ele permite criar fluxos de automação complexos arrastando e conectando componentes em um canvas interativo, sem necessidade de programação.

O que você pode fazer:

  • Extrair dados — de bancos de dados (PostgreSQL, MySQL, SQL Server, Oracle, SQLite), APIs HTTP, arquivos CSV
  • Transformar dados — filtrar, ordenar, mapear campos, agregar, mesclar datasets, aplicar regex
  • Carregar dados — inserir/atualizar em bancos de dados, exportar para CSV/JSON/XML/PDF/HTML
  • Automatizar ações — enviar emails com anexos, chamar APIs, executar rotinas ETL, registrar logs
  • Controlar fluxo — condições if/else, switch/case, loops, try/catch com retentativas, delays
  • Agendar execuções — triggers manuais, cron (agendamento), webhooks, eventos de API
Nota

O pipeline suporta 24 tipos de componentes distribuídos em 4 categorias: Entrada/Saída, Dados, Lógica e Ações. Cada componente pode ser configurado individualmente e conectado a outros para criar fluxos complexos.

Para adicionar um componente ao canvas:

  • Duplo-clique — clique duas vezes no componente para adicioná-lo automaticamente

2.3 Área de Trabalho (Canvas)

O canvas é onde você monta o pipeline visualmente:

  • Mover nós — clique e arraste qualquer nó
  • Conectar nós — clique na saída (bolinha à direita) de um nó e arraste até a entrada (bolinha à esquerda) de outro
  • Selecionar — clique em um nó para selecioná-lo e abrir suas propriedades
  • Deletar — selecione o nó e pressione Delete
  • Zoom — use a roda do mouse ou os botões da toolbar
  • Pan/Mover — clique em área vazia e arraste para mover o canvas
Dica

Os nós com 2 saídas (Condition, Try/Catch, API Call) têm a saída superior para o caminho de sucesso/verdadeiro e a inferior para erro/falso. O Switch/Case tem 3 saídas.

2.4 Painel de Propriedades

Ao selecionar um nó no canvas, o painel de propriedades aparece à direita com os campos de configuração específicos daquele componente. Todos os nós possuem:

  • Label — nome de exibição do nó (pode ser renomeado)
  • Parar ao falhar — se ativado, erros neste nó interrompem o pipeline todo
  • Variável de saída — nome da variável que receberá o resultado (componentes de dados)

2.5 Modos de Edição

Modo No-Code (Visual)

O modo padrão. Arraste componentes, conecte-os visualmente e configure propriedades no painel lateral. Ideal para a maioria dos usuários.

Modo Low-Code (Estruturado)

Um formato texto onde cada nó é representado como:

[tipo_componente] id=N label="Nome" pos=(X, Y)
  campo1 = valor1
  campo2 = valor2
  -> output_1 => 2.input_1

Modo Code (JSON)

Acesso direto ao JSON do Drawflow. Para usuários avançados que precisam manipular a estrutura internamente. Possui botões de Formatar (pretty-print) e Aplicar (carregar no canvas).

Sincronização Bidirecional

Ao trocar entre modos, o sistema sincroniza automaticamente. Alterações feitas em qualquer modo são preservadas.

PropriedadeTipoDescrição

Uso com Condition

Para bifurcar o fluxo baseado no resultado da rotina, defina output_variable = resultado e use com stop_on_error = false. No Condition, acesse a propriedade aninhada:

Importante: Usar {{resultado}} sem .sucesso retorna o objeto completo (array), que em comparações será sempre avaliado como verdadeiro, mesmo que a rotina tenha falhado. Sempre use .sucesso para verificar o resultado.

5. Componentes: Lógica

Condition (Se/Senão) Lógica

Avalia uma condição e bifurca o fluxo: verdadeiro ou falso.

1 entrada 2 saídas
CampoTipoDescrição
left_operandTextoValor da esquerda (suporta {{variável}})
operatorSeleção==, !=, >, <, >=, <=, contains, starts_with, ends_with, is_empty, not_empty, matches (regex)
right_operandTextoValor da direita

Saída 1 (superior) = condição VERDADEIRA — Saída 2 (inferior) = condição FALSA

Exemplo 1 — Verificar quantidade

left_operand = {{total_registros}}, operator = >, right_operand = 0. Se verdadeiro, prossegue com export; se falso, envia alerta “sem dados”.

Exemplo 2 — Verificar resultado de Rotina

Após uma Rotina com output_variable = resultado:

left_operand = {{resultado.sucesso}}, operator = ==, right_operand = true

✅ Verdadeiro = rotina executou com sucesso → prossegue normalmente
❌ Falso = rotina falhou → envia alerta ou trata o erro

Nota: Use acesso aninhado com ponto ({{var.propriedade}}) para acessar propriedades específicas de objetos. Sem o .sucesso, a variável retorna o objeto completo que sempre será avaliado como verdadeiro.

7. Sistema de Variáveis

O Pipeline Builder possui um sistema de variáveis que permite que os nós compartilhem dados entre si durante a execução.

Como usar variáveis

Use a sintaxe {{nome_da_variavel}} em qualquer campo de texto para referenciar o valor de uma variável.

Como criar variáveis

  • Variável de saída — Componentes de dados (SQL Query, HTTP Request, Transform, Rotina, etc.) têm campo output_variable que define o nome da variável com os resultados
  • Set Variable — Define manualmente variáveis com valores fixos ou compostos
  • Loop — Cria automaticamente {{item}} e {{_index}} dentro do loop
  • Counter — Cria/atualiza um contador numérico

Acesso aninhado (dot notation)

Quando uma variável contém um objeto (array associativo), você pode acessar suas propriedades usando ponto (.):

// Sintaxe geral
{{nome_variavel.propriedade}}      → acessa a propriedade do objeto
{{nome_variavel.prop.subprop}}     → acesso múltiplos níveis

⚠️ Importante: Usar {{variavel}} sem ponto retorna o objeto completo. Em comparações, um objeto (array) é sempre avaliado como true, mesmo que o conteúdo indique falha. Sempre acesse a propriedade específica para comparações corretas.

// Variável de SQL Query (output_variable = "dados")
{{dados}}          → o array completo de resultados
{{dados.rows}}     → array de registros
{{dados.total}}    → número total de registros

// Variável de Data Format (output_variable = "arquivo")

8. Como Funciona a Execução

Ao clicar em Executar , o pipeline segue estas etapas:

  1. Carregamento — O sistema lê a definição do pipeline (nós e conexões)
  2. Ordenação Topológica — Os nós são colocados na ordem correta de execução usando o algoritmo de Kahn (respeita as dependências)
  3. Execução sequencial — Cada nó é executado na ordem determinada:
    • O resultado de cada nó é salvo no contexto (variáveis)
    • O próximo nó pode usar os resultados anteriores via {{variáveis}}
  4. Tratamento de Ramificações — Nós condicionais (Condition, Try/Catch, API Call, Switch/Case) determinam qual ramo é executado. O ramo inativo é marcado como “pulado”
  5. Log detalhado — Cada nó gera um log com: status, duração, preview do resultado
  6. Registro — O resultado completo é salvo em tb_pipeline_execucoes e pode ser consultado na tela de Histórico

Tratamento de Erros

CenárioComportamento
stop_on_error = true (padrão)Pipeline para imediatamente ao encontrar erro
stop_on_error = falsePipeline continua para o próximo nó, erro é registrado
Try/Catch com retentativasTenta novamente N vezes com delay configurável antes de seguir para o catch
Notificação de falhaSistema envia notificação automática ao criador quando o pipeline falha
